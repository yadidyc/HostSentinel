# HostSentinel 与 Sigma Correlation 2.1.0 的功能对比

核对日期：2026-10-31。当前实现基线：提交 `606f9ba`。**当前是四类关联的受限实现，尚未达到较完整的 Sigma Correlation 2.1.0 支持。** 通用 `eventcorr` 包解决了跨领域复用，但它接收已分类的 `Hit`，不能替代 Sigma 规则解析与完整关联执行。

## 对比依据与版本边界

以 SigmaHQ [2.1.0 规范正文的固定修订](https://github.com/SigmaHQ/sigma-specification/blob/0c857d07da0e71eaaab2d667b3cce6f2c8469578/specification/sigma-correlation-rules-specification.md)为主，结合[官方 JSON Schema](https://github.com/SigmaHQ/sigma-specification/blob/0c857d07da0e71eaaab2d667b3cce6f2c8469578/json-schema/sigma-correlation-rules-schema.json)核对输入结构。[官方使用指南](https://sigmahq.io/docs/meta/correlations)用于交叉核对，不能用滚动更新的指南扩张固定版本承诺。

正文的类型总览仍只列四类，但其后续章节、版本历史和 Schema 包含三类 metric；本项目按七类核对。指南另列 `value_median`，固定 2.1.0 Schema 未列该独立类型，因此不计入七类覆盖。`group-by` 的必需性、`generate` 位置以及 percentile 的解释在官方材料间也存在差异；实现前需要锁定解释和测试预期，不能凭名称猜测语义。

## 当前覆盖与缺口

“部分”表示存在实现及局部测试，不代表该项已通过 2.1.0 一致性验收。“待补齐”属于目标内缺口，不是明确不做的功能。

| 功能 | 当前实现与证据 | 面向 2.1.0 的结论 |
| --- | --- | --- |
| `event_count` | 按事件键去重、窗口内计数；[匹配测试](../correlation_rule_match_test.mbt) | 部分；还需覆盖范围条件、零阈值及多规则重叠语义 |
| `value_count` | 单个字符串字段的不同已出现取值；同上 | 部分；多字段 `condition.field` 尚不支持，不能声称完整 |
| `temporal` / `temporal_ordered` | 无序角色分配、有序见证、含端点窗口；[通用内核测试](../eventcorr/eventcorr_test.mbt) | 部分；当前要求不同事件承担不同角色，等时间顺序与重叠选择器须对照规范样例明确验收 |
| `value_sum` / `value_avg` / `value_percentile` | [IR](../correlation_rule_ir.mbt)与内核均只有四类，没有 metric 数值模型 | 未实现，三类均待补齐；不能用宿主程序预计算代替库内实现 |
| `condition` 六种比较符 | 六种均可解析，但仅允许一个比较符、正整数阈值；[编译器](../correlation_rule_compile.mbt) | 部分；AND 范围条件、metric 数值阈值及边界值待补齐 |
| 引用基础规则及关联链 | 支持基础规则的 `id` / `name`、未知引用与循环检查；明确拒绝引用关联规则 | 部分；关联 DAG 的拓扑执行、中间结果时间与分组传递、证据回溯待补齐 |
| `group-by` / `aliases` | 主机规则按已列字段或别名分组；别名有测试 | 部分；任意映射字段受限，不能把手工提供 `Hit.group_key` 等同于标准规则自动执行 |
| `timespan` 与窗口 | 支持 `s/m/h/d`，另有本地 `w` 扩展；使用滑动窗口 | 部分；须补跨边界、溢出、等时间和链式窗口测试，不要求与所有 SIEM 的固定桶逐条一致 |
| 标准文档与元数据 | 强制 `id`、自定义正整数 `version`；`title` 可选；大部分元数据被拒绝 | 不兼容；需接受标准文档，保留并校验元数据，取消标准入口对自定义 `version` 的强制要求 |
| `generate` | 解析器不接受，执行器未定义基础/中间结果输出控制 | 未实现；需在离线执行器定义与标准意图对应的输出行为，并验证默认值与显式值 |
| YAML 与规则集合 | 多文档受限 YAML；不支持内联集合、锚点、跨文件集合加载 | 部分；官方样例的常见写法与规则集合加载需要覆盖，复杂 YAML 特性须显式诊断 |
| 基础 Sigma 检测规则 | 固定字段等值合取、`condition: selection`；没有通用 `logsource`、修饰符与布尔表达式 | 是端到端导入的独立缺口；需声明基础命中的提供接口及支持范围，不能宣称可直接运行任意 Sigma 规则 |
| 不支持功能的诊断 | 未知字段/类型/引用等会报错，不静默降级 | 已有基础；仍需为每项未支持语义增加负例和稳定诊断 |
| 主机身份扩展 | `correlation.identity`、身份等级和拒绝原因；[身份测试](../identity_correlation_test.mbt) | 项目扩展，不计入 Sigma 覆盖；标准执行路径不得隐式增加同主机条件，改变规则原意 |

官方规范给出了范围条件、关联链、别名和 metric 的行为要求；Schema 同时暴露出目前自定义文档格式与标准输入的差异。上表的“部分”必须通过对应测试逐项升级，不能以类型名称数计算兼容百分比。

## 明确不做的范围

本轮目标是离线 MoonBit 关联库及文件 CLI。明确不做 Splunk SPL、Elastic ES|QL 等 SIEM 查询生成器，也不承诺不同 SIEM 后端查询计划或固定桶结果完全一致；`generate` 在本地结果输出中的含义仍需实现。常驻采集、流式 watermark、分布式/持久化状态、真实隔离主机和自动处置不在本轮范围。完整 OCSF 类库、所有供应商日志解析器、所有 Sigma 基础检测修饰符也不属于本轮完整性承诺；它们与 Correlation 2.1.0 必须分开列明。

**七类关联、范围条件、关联链、标准文档元数据、别名和输出控制均不能列为“明确不做”。** 若继续排除这些能力，就应维持“窄子集”定位，不能以此回应评审对较完整 2.1.0 支持的要求。

## 补齐后的验收证据

先完成标准文档/规则集合、字段与数值模型、范围条件，再实现三类 metric 和关联 DAG；随后统一输出控制与诊断。每项应提供公开规则文件、输入、预期结果和负例，并由公共 API 与文件 CLI 读取同一份材料。至少包含七类关联各自的用例、失败登录聚合后成功登录的两层链、跨来源字段别名、范围条件、重复/乱序/缺失值、跨窗口边界及预算失败；现有跨领域用例继续验证通用内核复用。

percentile 尤其不能直接当作已确定的数值分位数：固定正文的例子使用字符串字段和低频比例描述，滚动指南则描述数值 percentile 参数。应保存具体分歧、选定参考实现/预期值并说明偏差，解决前保持未完成。Schema 校验只能证明结构，不能作为执行语义通过的证据。

当前检查为源码与现有测试的静态核对，未新增执行能力，未重跑一致性测试，未验证完整支持；既有 CI 通过仅证明现有实现回归通过。
