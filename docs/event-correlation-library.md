# 从主机检测到可复用事件关联：接口与证据

项目包含两个明确分层。`eventcorr` 包只接收调用者已分类的 `Hit`：稳定事件键、角色、来源、毫秒时间、分组键，以及供 `value_count` 使用的可选值。它不认识 `host`、`boot_id` 或任何安全事件类别；规则的角色、窗口、关联类型、比较符和阈值由调用者构造。公开入口 `@eventcorr.correlate(rule, hits)` 返回确定性的候选见证，包含输入索引、事件键、角色、来源、分组、起止时间和实际计数。分组键为空可代表全局范围；要隔离订单、服务或租户，应由调用者提供明确且稳定的分组键。

主机层仍保留外部 JSON/YAML 规则编译和 `HostEvent` 适配。它把规则命中的主机事件转换为 `Hit`，调用同一个 `eventcorr.correlate` 生成候选，再由 `correlate_identity_safe` 核对同主机、启动周期、会话、进程实例、父子关系、来源多样性和身份等级。这样，领域无关的窗口/计数/序列算法只有一份实现；旧 CLI 与主机检测公共接口保持不变。通用内核**不**自动解析 Sigma、OCSF 或原生日志，也不承担主机身份真实性判断。

## 三类输入共用一套内核

| 独立消费方式 | 角色与范围 | 可复现结果 |
| --- | --- | --- |
| 零售订单与付款，`examples/reuse/reuse_test.mbt` | `placed → paid`，按订单号分组，60 秒有序窗口 | 订单 17 的两条记录成链；订单 18 的付款不会跨组拼接 |
| 服务告警突增，同一消费包 | `alerted`，按服务名分组，30 秒内至少两条不同事件 | `service-a` 命中一次；`service-b` 只有一条，不命中 |
| 主机进程与联网，`fixtures/correlation/` | `process → network`，主机层要求同启动周期、同进程实例 | 正例成链；相同 PID 但不同进程启动时间的反例被身份层拒绝 |

运行 `moon test eventcorr`、`moon test examples/reuse`、`moon test multi_scenario_test.mbt`，可分别核对内核边界、跨领域消费和五套主机规则。`examples/reuse/moon.pkg` 只导入 `yadidyc/hostsentinel/eventcorr`，不导入根包或 CLI；改变业务角色和分组键无需修改、重编译内核源码。`correlation_rule_match.mbt` 是主机适配调用点，可检查它与非安全案例是否确实使用同一入口。

## 通用性的准确边界

这里的“通用”指**已分类事件的离线候选关联**：四种关联类型、精确分组、含端点滑动窗口、稳定见证和候选预算。它不提供任意 Schema 的自动字段发现、跨组连接、流式状态、持久化状态或真实因果推断。通用包按调用者给出的事件键去重；调用者须保证键在输入批次内标识同一条源记录，并负责把原始数据映射成角色、分组及不同值。主机包额外实施身份安全策略，不能把通用内核的候选直接称为已确认威胁。Sigma/OCSF 支持范围另见[兼容性矩阵](compatibility-matrix.md)。
